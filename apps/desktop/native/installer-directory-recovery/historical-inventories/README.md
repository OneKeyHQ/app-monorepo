# Historical Windows installer inventories

The recovery helper uses these inventories to migrate matching all-users installations at the default fixed-NTFS path. Each inventory covers a specific released payload and its installed uninstaller. The helper verifies the original files against the embedded inventory, stages the replacement, and uses the existing transaction for publication and rollback. It does not execute the historical uninstaller.

Every Setup SHA-256 below was checked against the digest published for the GitHub release asset. Each inventory records the directories and SHA-256 of every file extracted from the corresponding NSIS app archive, plus the embedded `Uninstall OneKey.exe` and `uninstallerIcon.ico` when present. The installer filename and the selected app archive identify the packaging variant and architecture. The inventory uses UTF-8 with LF endings and starts with `onekey-historical-inventory-v1` and the registered release. Remaining lines contain `d` or the lowercase SHA-256 followed by a tab and the relative Windows path.

On Windows, verify each extracted tree after placing its embedded uninstaller and optional icon at the app root. Run `OneKeyInstallerDirectoryRecovery.exe verify-historical-tree <release> <absolute-app-root>` on the assembled tree. Preserve prior inventories when adding versions so a matching installer can recover existing journals and still authenticate an interrupted backup cleanup.
